# Spike S-05 — Open-weight Meta models as an LLM fallback

Date: 4 Nov 2026 · Resolves: fallback-model selection for `MetaClient`

## What was checked

- Official Meta model catalog: `https://dev.meta.ai/docs/models.md`
- Relevant finding: `muse-spark-1.1/1.2/1.3` are hosted on Meta Model API.
- Relevant finding: Muse Spark Open and Muse Glimmer are open-weight and are
  not callable over Meta Model API. They must be self-hosted through a
  runtime such as SGLang, vLLM, TensorRT-LLM, llama.cpp, or ExecuTorch, or
  called through a hosted inference provider.

No API key was used, and no secret is recorded in this note.

## Implementation consequences

1. Do not hardcode open-weight checkpoint names as Meta Model API model IDs.
   The fallback model identifier is deployment-defined.
2. Implement fallback as separately configured OpenAI-compatible chat
   endpoints: ordered `META_FALLBACK_MODELS`, `META_FALLBACK_BASE_URLS`,
   and optional `META_FALLBACK_API_KEYS` lists.
3. Preserve RippleWitness's local-first network boundary: accept a fallback
   endpoint only on the same origin as the configured Meta client or on
   loopback. Do not silently route prompts to an arbitrary remote provider.
4. Keep `muse-spark-1.3` as the primary model and try fallback only after a
   transport/server/unreachable-model failure, not for authentication or
   malformed-request failures.
